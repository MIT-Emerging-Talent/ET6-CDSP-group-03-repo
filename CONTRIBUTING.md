# 🧑‍💻 Contributor Guidelines

Thank you for considering contributing to this project!

To ensure a smooth collaboration, please follow the guidelines below.

## Repository folders

/collaboration: Communication, norms, learning goals, retrospectives.
/requirements.txt: includes all python requirements.
/0_domain_study → /6_final_presentation: Project work per milestone.

## How to Contribute

### 1.Fork the repository to your GitHub account

### 2.Clone your fork locally

### 3.Create a new branch for your work

You can:

* Report bugs.

* Fix bugs.

* Suggest changes or improvements to documents.

* Improve documentation.

* Refactor or improve existing code.

## contributing Guidelines

* Follow the existing code style and structure.

* Write clear, concise commit messages.

* Include comments where necessary.

* document your changes in a clear way, weather you are improving a code or a document.

* follow naming conventions and CI formatting standards.

## Lint & Format

Our CI checks require:

* Markdown linting
* Python formatting (ruff format)
* Python linting (ruff and pylint)
* Folder/file structure cleanliness (ls-lint)

Ensure your code passes all linters and formatters.

## 🔄 Pull Request Process

* Ensure your branch is up to date with the latest main (or dev) branch:

* Push your branch to your fork

* Open a pull request on the original repository.

Clearly describe:

* What your changes do

* Why they are needed

* Any relevant issue number (e.g., Closes #12)

* Be open to feedback and ready to make changes.
